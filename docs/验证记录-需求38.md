# 第 1 条:深绿像素被判成未覆盖

## 根因

OSM 渲染用 alpha 表示"未覆盖",而 alpha 取自 `vrt.read_masks(1)` —— **只看第 1
波段(R)**。VRT 又被设了 `nodata=0`(`_warped_vrt_kwargs`),GDAL 的 nodata 判定是
**逐波段**的,于是只要 R 为 0 就算未覆盖。深绿植被的 R 常为 0,成果里就是一片片
透明麻点。

**实测确认**:对等价的 3 波段源,`VRT read_masks(1)` 中 0 的占比 **0.0012**,
与 `band1==0` 的占比**完全相同** —— 掩膜确实按 `R==0` 判。

## 为什么只在裁剪任务上出现

未裁剪时 OSM 复用带 alpha 的 `{name}_z{z}.tif`(掩膜精确、无此问题);
裁剪时它被裁过不能复用,只能用 geotiff 阶段**裁剪前**留存的自拼源
(`.osm_src_z{z}.tif`,由 `runner` 第 609 行 `copyfile` 而来)—— 那份是
**3 波段 RGB、无 alpha**,于是落到 `nodata=0` 这条路上。

## 修法

alpha 取**各波段掩膜的并集**:

* 源自带 alpha 时,三个波段的掩膜都取自那个 alpha → 并集就是它;
* 无 alpha 时并集恰好等于"任一波段非 0",即 `mosaic_to_geotiff` 的覆盖约定
  (该函数里"保持黑色填充,与原全图 canvas 语义一致"的注释就是这条)。

用 `read_masks`(默认 nearest 重采样)而不是对像素值判断:遮罩边界不会被插值
糊开 —— 否则数据边缘会多出一圈不透明的过渡像素(**第一版就是这么写的,实测在
合成测试里把"全零"瓦片写成了不透明**,已换掉)。

# 第 2 条:OSM 复用 TMS 的断层策略

## 原先的行为

```python
osm_levels = list(range(min(OSM_MIN_LEVEL, z_max), z_max + 1))
export_osm(src_of_z_max, osm_levels, ...)      # 一个源切所有级别
```

即**只用最高级的拼接图降采样出全部级别** —— 就是需求说的"只切最高级"。

## 改法

复用 `_source_tms_plan_for_task(ctx)`(读 `task.tms_source_strategy`,与 TMS
**同一个字段、同一套策略**),按"源层级 → 输出层级"分组,每组用**自己那一级**的
拼接图切。

分组数取决于级别是否连续(实测):

| 级别 | 默认(连续高层兜底) | 保留每个输入层级 |
|---|---|---|
| 1..12(连续) | **12 组**,每级各用自己的源 | 12 组,同上 |
| 18/17/16/13 | 3 组:z16 源出 z1..z16、z17/z18 各出自己 | 4 组:z16 源出 z14..z16、z13 源出 z1..z13 |

> ⚠️ 它不是"和原先完全一致":**常规的连续级别也从"一个源"改成了"逐级取源"**,
> 这正是第 2 条要的效果。(我最初在代码注释里写成了"只有一组、行为不变",已改正 ——
> 错误的注释比没有注释更糟。)

## 顺带修掉的自拼路径 bug

原自拼分支写死 `range_for_bbox`(**4326** 网格)**且不传 crs**;对墨卡托源
(Google/Esri)会按 4326 的行列号去读按 3857 命名的缓存 —— 一张都命中不了,整幅
拼成空白。常规情况下走的是"复用"分支,这条路径没被覆盖到,问题一直藏着。

实测两套网格在 z6 上的行列号:

```
墨卡托 z6: col 52..52  row 26..26
4326   z6: col 52..52  row 10..10     ← 行号完全不重叠
```

修法:范围用 `_range_fn_for(provider)`、crs 按网格取(`GEO_MERCATOR` → 3857)。

## 另外的改动

* **geotiff 阶段**:裁剪前留存的未裁剪源，从"只留最高级"改为留存**计划要用到的
  那几级**(见 OSM 的分组说明)。
* **进度**:分组数可能不少(连续级别时每级一组),故进度按全部分组**累计**上报 ——
  逐组重置会让进度条来回跳。
* **前端**:断层策略选项原先只在勾了 TMS 时显示(`showTmsSourceStrategy`),改为
  **勾 TMS 或 OSM 都显示**;标签由「TMS 断层策略」改为「瓦片断层策略」,提示文案
  注明两者共用。
