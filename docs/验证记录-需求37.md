# 验证记录 — 需求37:下载切片后的文字标注比原始模糊

> 日期:2026-09-29
> 需求:下载切片后的数据,文字标注比原始标注模糊很多,看看是什么原因并修复

## 根因

Google/Esri 是 **Web 墨卡托(3857)** 源,而 TMS 导出用的是 gdal2tiles 的
**geodetic(4326)** 网格 —— 两者不同构,必须重投影。链路:

```
下载瓦片(3857,清晰) → 拼接 GeoTIFF → 重投影到 4326   ← 损失在这里(bilinear)
                                   → 切片(geodetic TMS)  ← 几乎无损
                                   → 前端显示时 OL 再 4326→3857 重投影 ← 又掉一次
```

细笔画的文字标注对重采样最敏感,所以"影像看着还行、文字糊得明显"。

**天地图源不受影响**:它的瓦片本来就是 4326,走 `export_tms` 的无损直映射
(`core/tms.py` 的 docstring 明确写了这个分工:重采样版只供"没有对应 4326 瓦片
缓存"的数据用)。所以 `tms` 阶段注册表里那句「与天地图 EPSG:4326 无损直映射」
只对天地图成立,对墨卡托源是误导。

## 证据

### 各阶段分解(同一块地面,统一到 1024×1024 同一个 bilinear 核)

| 阶段 | 拉普拉斯方差 | 相对原始 |
|---|---|---|
| Y 原始 3857 镶嵌图 | 54.8 | 100% |
| X 重投影源(切片前) | 37.3 | **68%** |
| Z 实际 TMS 瓦片(切片后) | 36.2 | **66%** |

**损失全在重投影那一步**(68%),切片几乎无损(68%→66%)。

### 不同重采样核(原始 3857 镶嵌图 → 同一瓦片网格)

| 核 | 保留高频能量 |
|---|---|
| bilinear(改前) | 65% |
| **cubic(改后)** | **80%** |
| lanczos | 90% |
| 3857→3857(不重投影,即 OSM 路径) | **100%** |

不用 lanczos:它在高对比边缘产生振铃,文字上比"略软"更显眼。

### 真实数据上换核的实测收益

对任务 `2-Google卫星影像_20260929_084759` 的 z14 拼接图:

| 核 | 拉普拉斯方差 |
|---|---|
| bilinear(改前) | 4277 |
| **cubic(改后)** | **6534** |

→ **1.53 倍**(+53%),比合成图的 1.23 倍更明显。

> ⚠️ 我前两次测量都因取窗越过了源图边界而失真(`read` 会裁剪窗口、
> `window_transform` 用的是未裁剪窗口 → 数组与 transform 不一致)。第一次
> 得出"切片掉 45%"、第二次得出"切片掉 71%",都是假的;修正后才定位到
> 重投影这一步。记下来免得按错的数据下结论。

## 修法(两条)

### ① 默认瓦片格式按源自身的网格选

`core/formats.py::default_on_stage_keys(provider, stages)` 在注册表的静态
`default_on` 之上改写瓦片格式:

| 源 | 默认瓦片格式 | 理由 |
|---|---|---|
| 天地图(4326) | `tms` | 与源同构,无损直映射 |
| Google/Esri/DEM(3857) | `osm` | 3857→3857 无损,且前端按 3857 渲染、不再重投影 |

为什么不能只靠静态 `default_on`:"哪个瓦片网格无损"取决于**源自己的网格**,
不是格式的固有属性。`/api/capabilities` 的 `default_on` 改用它计算 ——
前端就是读这个字段决定默认勾选的,所以后端改完必须让接口用上(已接)。

实测结果:

```
tianditu_img   默认导出 = ['geotiff', 'tms']     (不变)
google_img     默认导出 = ['geotiff', 'osm']     (原 tms)
esri_imagery   默认导出 = ['geotiff', 'osm']     (原 tms)
esri_terrain   默认导出 = ['dem', 'osm']         (原 tms;terrain 由前端补)
```

### ② TMS 仍需时,重投影核换 cubic

`postprocess.reproject_geotiff` 新增 `resampling` 参数(默认仍是 `bilinear`,
**不改**用户选的"输出坐标系"那条路),`runner._mercator_raster_source` 传
`Resampling.cubic`。alpha 与掩膜恒用 nearest(它们是有效性边界,插值会糊出灰边)。

### ③ 界面提示(用户手动勾回 TMS 时)

`ProcessDialog` 在勾了 TMS 且源是墨卡托时提示会重投影、建议改勾 OSM ——
后端已把默认改掉,这条兜住"用户手动勾回来"的情形,别默默拿到发虚的成果。
不含天地图(它同构、本就无损),也不含 DEM(无文字,默认同样已翻成 OSM)。

## 遗留

- **已有的 TMS 成果不会自动变清晰** —— 要重新导出(或补导 OSM)。旧成果里的
  发虚是重投影时丢掉的,事后无法找回。
- 前端显示 geodetic TMS 时那次客户端重投影仍在(44% 里的另一半)。只有走 OSM
  (3857)才能完全避免 —— 这正是把 OSM 设为默认的原因。
