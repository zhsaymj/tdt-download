# 验证记录 — 所有影像数据源默认勾选「叠加路网注记」

> 日期:2026-09-29
> 需求:新增需求和优化35 第 2 条(第 1 条是日志按日期轮转,已完成)

## 需求

所有类型的影像数据,在参数选择的高级选项里,「叠加路网注记」都默认勾选。

## 现状:判据只覆盖了天地图

默认值本来就有单一来源,只是判据太窄 —— `frontendvue/src/utils/taskDefaults.js`:

```js
export function defaultAnnotateForProvider(provider) {
  return isTiandituRasterProvider(provider)   // 只有 tianditu_img/vec/ter
}
```

这是需求13-5「高级选项 影像数据 默认勾选 叠加路网注记」留下的:当时只有天地图
三个影像源,Google/Esri 加进来后判据没跟上。

实测(改动前):

| 数据源 | `canAnnotate` | `defaultAnnotateForProvider` |
|---|---|---|
| `tianditu_img` / `_vec` / `_ter` | true | **true** |
| `google_img` | true | **false** ← 该勾没勾 |
| `esri_imagery` | true | **false** ← 该勾没勾 |
| `esri_terrain` / `local_dem` | false | false |

## 改法

`defaultAnnotateForProvider` 直接用 `canAnnotate`(provider.js),不再另写一份名单。
两者语义本就重合 —— "这个源能叠注记吗" / "默认要不要叠" —— 分头维护必然漂移。

同时把 `taskDefaults.js` 里自己抄的那份 `isDemProvider` 也删掉、改为从
provider.js 导入(它原本与 provider.js 那份不一致,见下)。

## 顺带修掉的 bug:`local_dem` 被标成「影像」

去重时发现两份 `isDemProvider` 名单不一样:

| 位置 | 名单 |
|---|---|
| `provider.js` | `['esri_terrain']` |
| `taskDefaults.js`(已删) | `['esri_terrain', 'local_dem']` |

于是 `provider.isDemProvider('local_dem')` 返回 **false**,`local_dem` 任务在
任务队列 / 数据管理里被标成「影像」并配影像配色。与之前 `esri_imagery` 被标成
「地形」是同一类名单漂移(本项目已踩过三次)。

修法:名单收敛到 provider.js 一处,取并集 `['esri_terrain', 'local_dem']`。

波及面核查(全部是修对了):

| 受影响处 | 改动前 | 改动后 |
|---|---|---|
| `TaskQueue` 卡片标签/配色 | 影像 | **地形** ✓ |
| `taskKindOf({provider:'local_dem'})` | `'image'` | `'dem'` ✓ |
| `DataDialog` 类型过滤 | 归到影像 | 归到地形 ✓ |
| `canAnnotate('local_dem')` | false | false(本就由 LOCAL_FILE_PROVIDERS 兜住) |

## 未处理:两处估算不随勾选框刷新(需要你定夺)

改动让「默认勾上 → 用户取消勾选」成为常态,于是暴露出下面两处**既有**问题:

### 1. ProcessDialog:切换勾选框后估算数字不更新

`est` 只在「打开对话框 / 切数据源 / 改范围」时重算(`loadEstimate` 的调用点:
`initForCurrentSource`、`watch(form.provider)`、`watch(drawStore.bbox)`),
**没有监听 `form.annotate`**。

后果:默认勾上时打开 → 估算含注记(对);用户取消勾选 → 数字仍是含注记的 2 倍。

### 2. RedownloadDialog:不传 `annotate`,改在本地 ×2

`RedownloadDialog.vue:166` 的 `api.estimate` 请求没带 `annotate`,然后在
`selectedSummary`(第 187 行)里 `tiles *= 2; bytes *= 2`。两个后果:

- **每级明细列与总计自相矛盾**:明细列(`levelSize`)是未含注记的值,总计却是 2 倍;
- **级别含 z19+ 时 ×2 是错的** —— 注记只到 18 级。ProcessDialog 的注释
  (第 460~462 行)正是为修这个而改成"传 annotate 给后端、前端不乘"的,
  RedownloadDialog 没跟上。

两处的修法都需要"勾选框变化时重新估算",属同一个决策(是否为一个 UI 勾选动作
加一次网络请求),所以没有单方面改。
