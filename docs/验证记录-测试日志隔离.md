# 验证记录 — 测试不再污染生产日志

> 日期:2026-09-29
> 关联需求:35(日志按日期轮转)的收尾 —— 轮转让"按天分文件"成立,
> 但测试噪音混在每天的份里,正好抵消这个目标。

## 问题

`backend/core/logs.py` 在 **import 时**就挂真实文件 handler(`data/logs/app.log`),
于是任何 `import backend.*` 的测试都会把日志写进用户的生产日志。

实测(改动前,`data/logs/app.log`):

| 指标 | 值 |
|---|---|
| 总行数 | 33,045 |
| 测试噪音行 | **1,464(4.4%)** |
| 文件大小 | 3.16 MB |
| 噪音最多的日子 | 09-24(653 行)、09-28(620 行)、09-21(109 行) |

噪音长相:

```
2026-09-29 11:28:34 [INFO] 登记服务 测试(imagery):C:\Users\ADMINI~1\AppData\Local\Temp\tmp4au2vbav
```

一次全量测试就让文件从 3.28 MB 涨到 3.31 MB(+27 KB)。

## 改法

`core/logs.py` 新增 `_resolve_log_dir()`,按三级判定日志目录:

| 条件 | 落点 |
|---|---|
| 设了 `TDT_LOG_DIR` | 用它(运维/调试可改;测试也能显式覆盖) |
| 运行在 unittest 里 | 临时目录,并把路径**写回 `TDT_LOG_DIR`** |
| 其他(生产) | `data/logs/` |

第三条是生产路径,必须保持原样;第二条的"写回环境变量"是为了覆盖
**测试 spawn 出的 worker 子进程** —— 子进程里没有 `unittest`,单靠进程内判定会漏,
靠继承环境变量才不漏。

## 走过的弯路(记下来免得重犯)

**第一版把引导放在 `tests/__init__.py`(新建该文件,设 `TDT_LOG_DIR`),全量测试红了 7 项。**

根因:`unittest discover tests` 把 `top_level_dir` 就设成 `tests/` 本身,模块被导入为
**顶层模块** `test_logs_rotation`(不是 `tests.test_logs_rotation`),于是
`tests/__init__.py` **根本不执行**。只有显式写 `python -m unittest tests.test_x`
时它才执行 —— 所以"测试引导"能不能生效取决于调用方式,不能当防线。

证据:失败名单里模块名没有 `tests.` 前缀,且同时报 `_file_handler()` 返回 None
(因为 `logs.py` 的 unittest 兜底生效、没挂文件 handler)。

**结论:防线放在被测代码里(`logs.py`)才与调用方式无关。** 该文件已删除。

## 代码侧验收

| 项 | 结果 |
|---|---|
| 后端全量 | **602** 通过(基线 594 + 本项 8) |
| 前端 | 166(未改动前端) |
| 跑完全量后真实日志大小 | 3,337,811 字节,**前后一致**(零增长) |

### 三层防线各一条护栏(`tests/test_logs_isolation.py`)

| # | 防线 | 护栏 |
|---|---|---|
| 1 | 测试进程落临时目录 | `TestResolveLogDir::test_test_process_gets_temp_dir_not_real_dir` |
| 2 | 测试的子进程继承同一目录 | `TestRealLogNotWrittenByTests::test_subprocess_of_test_process_writes_no_real_log` |
| 3 | 生产进程仍写 `data/logs/` | `TestProductionProcessStillWritesFile` + `test_production_process_gets_real_dir` |

第 3 条是防"修过头":若把生产进程也改成不落盘,那是**静默丢日志**,比污染更糟。

### RED 校验(不是真空通过)

把 `logs.py` 还原到改动前再跑:

```
ERROR: test_logs_isolation (unittest.loader._FailedTest)          ← _resolve_log_dir 不存在
ERROR: test_base_filename_is_app_log_in_configured_dir            ← TDT_LOG_DIR 未设 → KeyError
Ran 10 tests — FAILED (errors=2)
```

同时真实日志在那次运行中涨了 125 字节 —— 反向印证了污染路径。

## 断言方式说明

一律用"内容里有没有那条探针"判断,不用文件大小 —— 用户的服务进程可能同时在写
同一个文件,比大小会 flaky。读的也只是 `[运行前大小, 末尾)` 这一段增量。

## 遗留

历史噪音(1,464 行)仍在 `data/logs/app.log` 里,与真实日志交错,没有自动清理 ——
清理需要按行过滤用户的生产日志,属破坏性操作,留给用户决定。
