# 日志按日期轮转 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `data/logs/app.log` 的轮转从"按大小(5MB,从未触发)"改为"按日期",保留 180 天;并确保前端「运行日志」面板不受影响。

**Architecture:** 换用标准库 `TimedRotatingFileHandler`(一处 import + 一处构造)。选它成立的关键前提是**worker 子进程不持有文件句柄**(`install_forwarding` 清空 handler 换成队列转发),所以多进程轮转的已知隐患在本项目不存在 —— 无需自定义 handler。面板走内存环形缓冲,与文件解耦,不做任何面板侧改动。

**Tech Stack:** Python 标准库 `logging.handlers`、标准库 unittest、Vue3(仅一行文案)。

**设计文档:** `docs/superpowers/specs/2026-09-29-日志按日期轮转-design.md`(下称"设计 §N")

---

## 关键前提(动手前必读)

1. **轮转本来就存在,只是从未触发。** 现状是 `RotatingFileHandler(maxBytes=5MB, backupCount=3)`;实测 26 个使用日共 3.2MB、**最大单日仅 686KB** —— 要累积 26 天才转一次。所以本次不是"加轮转",是"换判据"。

2. **`TimedRotatingFileHandler` 的多进程隐患不适用本项目,但不要假设。** 它靠进程内时间判断轮转,多进程会重复轮转。本项目 worker 的 handler 被 `install_forwarding` 清空、换成队列转发,**只有主进程写文件**。`tests/test_log_forwarder.py` 已在守这一点(断言 install 后只剩 1 个 handler)——本次改动后**必须确认它仍绿**。

3. **面板与文件是解耦的,不要"顺手"改它。** `/api/logs` 读 `_ring`(内存环形缓冲),`stores/task.js` 的 WS 分支收实时 `log` 消息 —— 两条来源都不碰文件。保持现状即为满足需求。

4. **`utc` 不要传。** 默认 `False` 用本机时间,与界面上看到的日志时间戳一致;传 `True` 会让轮转点与文件名日期错开 8 小时。

5. **测试基线**(2026-09-29 实测):后端 **585** 通过、前端 **166** 通过。

**运行测试的命令**(项目根目录下):

```bash

cd frontendvue && node --test "src/**/*.test.js"                   # 前端
```

创建 `tests/test_logs_rotation.py`:

```python
"""日志按日期轮转,以及"面板不受轮转影响"的行为护栏。

背景:原实现是 RotatingFileHandler(maxBytes=5MB, backupCount=3),但实测
26 个使用日只累积 3.2MB、最大单日 686KB —— 5MB 阈值要 26 天才转一次,
文件会跨月累积。改为按日期(TimedRotatingFileHandler, midnight)。

多进程隐患不适用本项目:worker 的 handler 被 install_forwarding 清空换成
队列转发,只有主进程写文件(见 tests/test_log_forwarder.py 的护栏)。
"""
import time
import unittest
from logging.handlers import TimedRotatingFileHandler

from backend.config import ROOT
from backend.core.logs import logger, recent_logs

#: 日志文件路径(与 core/logs.py 的 _setup() 保持一致)
LOG_FILE = ROOT / "data" / "logs" / "app.log"


def _file_handler():
    """取 logger 上那个写文件的 handler;没有则 None。"""
    for h in logger.handlers:
        if isinstance(h, TimedRotatingFileHandler):
            return h
    return None


class TestRotationConfig(unittest.TestCase):
    def test_uses_timed_rotating_handler(self):
        """★ 核心 ★ 必须是按日期的 handler,不是按大小的。"""
        from logging.handlers import RotatingFileHandler
        h = _file_handler()
        self.assertIsNotNone(h, "未找到文件 handler —— 日志不会落盘")
        self.assertNotIsInstance(h, RotatingFileHandler,
                                 "仍是按大小轮转(RotatingFileHandler)")

    def test_when_is_midnight(self):
        h = _file_handler()
        self.assertIsNotNone(h)
        self.assertEqual(h.when, "midnight",
                         "轮转点应为每天零点,生成 app.log.<日期>")

    def test_backup_count_is_180(self):
        h = _file_handler()
        self.assertIsNotNone(h)
        self.assertEqual(h.backupCount, 180, "保留期应为 180 天")

    def test_utc_is_false(self):
        """用本机时间 —— 与界面上的日志时间戳一致。
        设 True 会让轮转点与文件名日期错开 8 小时。"""
        h = _file_handler()
        self.assertIsNotNone(h)
        self.assertFalse(h.utc)

    def test_encoding_is_utf8(self):
        h = _file_handler()
        self.assertIsNotNone(h)
        self.assertEqual(h.encoding, "utf-8",
                         "日志含中文,非 utf-8 会乱码/报错")

    def test_base_filename_is_app_log(self):
        h = _file_handler()
        self.assertIsNotNone(h)
        self.assertEqual(h.baseFilename, str(LOG_FILE))


class TestPanelUnaffectedByRotation(unittest.TestCase):
    """★ 需求明确要求 ★ 不管怎么新建文件,最新日志都要在运行日志面板展示。

    面板走的是内存环形缓冲(/api/logs → recent_logs → _ring),不是文件 ——
    这条测的就是这个解耦不被破坏。用行为验证而非断言源码:把文件改名
    (正是 TimedRotatingFileHandler 的动作)后,面板仍须能看到刚才那条。
    """

    def test_recent_logs_survives_file_rotation(self):
        # ⚠️ 用 handler 自己的 doRollover(),**不要用 shutil.move 模拟**:
        # 日志文件正被 handler 持有打开句柄,Windows 上移动它会抛
        # PermissionError [WinError 32];而 shutil.move 的降级路径会先复制
        # 成功、再 unlink 失败,留下一个残留副本(实测确认)。
        # doRollover 走的是真实轮转路径,比模拟更贴近要验的东西。
        h = _file_handler()
        self.assertIsNotNone(h, "未找到文件 handler")
        self.assertTrue(LOG_FILE.exists(),
                        f"前提不满足:{LOG_FILE} 不存在,该环境无法验证本护栏")

        marker = f"轮转护栏-{time.time_ns()}"
        logger.info(marker)
        self.assertIn(marker, [x["msg"] for x in recent_logs(50)],
                      "写入后立刻应能在面板可见")

        # 只清理本次轮转**新产生**的文件 —— 不动目录里原有的历史日志
        # (若测试当天已发生过真实轮转,app.log.<今天> 是用户的东西)。
        before = {p.name for p in LOG_FILE.parent.iterdir()}
        h.doRollover()
        created = [p for p in LOG_FILE.parent.iterdir()
                   if p.name not in before]
        try:
            # 文件已轮转(原 app.log 被改名),面板仍须能看到刚才那条
            self.assertIn(marker, [x["msg"] for x in recent_logs(50)],
                          "日志文件被轮转后,面板读不到最新日志 —— 解耦被破坏")
        finally:
            for p in created:
                try:
                    p.unlink()
                except OSError:
                    pass

        # 轮转后 handler 应能按需重建文件继续写
        logger.info("轮转后继续")
        self.assertTrue(LOG_FILE.exists(), "轮转后文件未重建,后续日志会丢")


class TestRepeatedSetupIsIdempotent(unittest.TestCase):
    """_setup() 由 _tdt_ready 守卫,不该重复挂 handler。

    重复挂会让每条日志写两遍(文件里出现重复行)。
    """

    def test_setup_twice_adds_no_handler(self):
        from backend.core.logs import _setup
        before = len(logger.handlers)
        _setup()
        _setup()
        self.assertEqual(len(logger.handlers), before,
                         "_setup() 不幂等 —— 重复调用会重复挂 handler")


if __name__ == "__main__":
    unittest.main()
```
