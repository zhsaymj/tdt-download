# 底图与数据源双向同步 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让图层面板的「底图」与下载对话框的「数据源」双向同步 —— 切任一方,另一方立即跟上(仅当目标在对方列表中)。

**Architecture:** 同步逻辑留在 `ProcessDialog.vue` 内部(`form.provider` 是它的局部表单状态,不提升到 store)。两个列表的成员判定各自留在列表所在处:下载列表用该组件自己的 `providerOptions` 派生,底图列表从 `basemap.js` 导出 `isBasemapKey`。**不另抄交集数组** —— 那在列表增删时必然漂移。

**Tech Stack:** Vue3 + Pinia + TDesign、Node 内置 test runner(读 `.vue` 源码做断言)。

**设计文档:** `docs/superpowers/specs/2026-09-29-底图与数据源同步-design.md`(下称"设计 §N")

---

## 关键前提(动手前必读)

1. **两个列表只有 5 个键重合**(设计 §2 实测)。交集:`tianditu_img`/`tianditu_vec`/`tianditu_ter`/`google_img`/`esri_imagery`。只在底图:`google_hybrid`/`google_road`/`google_terrain`。只在下载列表:`esri_terrain`/`osm_buildings`/`local_vector`。**所有同步都必须带成员判定**,否则会把 `esri_terrain` 设成底图这类无效组合。

2. **这是强耦合**(设计 §6,用户已确认):切底图会连带改下载目标。用户接受了这个取舍,并用"数据源旁加提示"缓解。**不要**擅自退回"仅改默认值"。

3. **防抖动是必需的,不是优化**。两个 watch 互相触发;设同值不触发 Vue watcher 所以本就收敛,但 `basemapStore.setKey` 会 `apply()`(移除并重建底图图层)—— 不加 `!==` 守卫会导致**每次打开对话框都闪一下**。

4. **`resetFormState` 每次打开对话框都执行**(`initForCurrentSource` 第一行),它把 provider 写死回 `tianditu_img` —— 这正是"底图已是 Google 却默认天地图"的根因,必须一并改。

5. **测试基线**(2026-09-29 实测):前端 **152** 通过。`.vue` 的测试方式是**读源码做断言**(见 `ProcessDialog.reset.test.js`),本次沿用。

**运行测试的命令**(项目根目录下):

```bash
cd frontendvue && node --test "src/**/*.test.js"   # 必须 glob 直参,Node 24 下目录直参会误报
npm run build                                      # 语法/构建验证
```

/**
 * 该 key 是否是底图列表中的一项。
 *
 * 用于「数据源 → 底图」的同步判定:数据源切到只在下载列表里的键
 * (如 esri_terrain)时,底图不该跟着变。

 * 不会漂移(这个项目为此栽过好几次)。
 */
export function isBasemapKey(key) {
  return BASEMAP_OPTIONS.some((x) => x.value === key)
}

- [ ] **Step 6: 改 ④ —— 方向二:底图 → 数据源(新增 watch)**

紧接在方向一那个 watch **之后**插入:

```js
// 底图切换 → 同步数据源。仅当该底图在本对话框可下载时才改:
// 如 Google 路线图只在底图列表里,切到它不动数据源。
//
// 这个 watch 会通过上面的 watch 回写底图,形成一次往返;因为设同值不触发
// Vue watcher,且这里有同值守卫,一轮即收敛。守卫不可省 ——
// basemapStore.setKey 会 apply()(移除并重建底图图层),不守卫会闪屏。
watch(() => basemapStore.key, (k) => {
  if (!isDownload.value) return
  if (!DOWNLOAD_KEYS.has(k)) return      // 不在下载列表 → 不动
  if (form.provider === k) return        // 已是它 → 不动
  form.provider = k
})
```
