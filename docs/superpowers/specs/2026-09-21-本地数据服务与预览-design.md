# 本地数据服务与预览 — 设计文档

> 需求来源:`docs/input/新增需求/需求描述2.md` 的「新增需求和优化31」
> 日期:2026-09-21
> 范围:**只做需求31**。29(导入范围解析失败)、30(层级纹理黑色碎片)不在本次范围。

## 1. 问题与目标

### 现状

本工具当前的成果只能通过**任务**访问:

- 预览页 `/preview.html?id=<任务id>` 依赖任务记录(`PreviewApp.vue::init` 开头即校验 `id`,缺失直接报错)。
- 二维叠加走 `/output/<目录>` 静态挂载,而 `/output` 只服务 `settings.output_dir` 这一个根。
- 三维查看只认任务产出目录的 `3dtiles/`、`terrain/`。

三个后果:任务记录删了成果就打不开;工具目录外的成果(别人给的瓦片包、QGIS 导出的 3d tiles)完全看不了;别的服务想拿这些成果当数据源,没有稳定可达的地址。

### 目标

1. 在**系统界面顶栏**新增「服务」菜单,把本地目录发布成长期可访问的数据服务,提供可复制的访问地址与开关。
2. 在**预览界面**新增「添加服务图层」,把已开启的服务叠加到三维场景。
3. 在**主界面图层列表**同样能从服务添加预览,透明度 / 层级 / 定位与任务图层一致。
4. 服务按 **模型 / 影像 / 矢量 / 地形** 四类归档。

## 2. 核心设计决策

这些决策贯穿全文,先集中列出。

| # | 决策 | 理由 |
|---|---|---|
| D1 | **一个可访问端点 = 一个服务** | 让"复制访问地址"有确定语义。`output/怀化不动产_全量/` 里的 `3dtiles/` 是一个服务,`tms/` 是另一个。代价是服务数量多,用分类+筛选化解。 |
| D2 | **默认候选扫文件系统,不读数据库** | 实测:库中 106 条 `output_path` 记录,**100 条目录已不存在**(成果被清理但记录留存)。读库会生成 100 个死服务;扫 `settings.output_dir` 实际得到 6 个目录、约 8~10 个服务。 |
| D3 | **落盘持久化到 sqlite,新增服务默认关闭** | 服务是长期配置,重启后地址不能变(其他服务配一次要长期有效)。默认关闭保证"不主动暴露"。 |
| D4 | **端点不带 token,不做访问限制** | 用户明确选择。默认 `server.host = 127.0.0.1` 时实际暴露面仅本机,其他本机服务可访问;仅当改为 `0.0.0.0` 时才对局域网开放。 |
| D5 | **两条来源,一个渲染出口** | 服务图层进入 `overlays.js` 时,`desc` 结构必须与 `core/overlay.py::list_layers()` 输出**逐字段对齐**,从而零改动复用透明度/层级/定位。 |
| D6 | **服务是指向,不是拥有** | 移除服务只删注册记录,绝不动磁盘文件。任务被 purge 时服务不自动删除,只标记失效。 |

## 3. 后端设计

### 3.1 数据模型

新增 `services` 表。沿用 `db.py` 既有的 `_SCHEMA` + `_MIGRATIONS` 手动加列模式(SQLite 不支持 `ADD COLUMN IF NOT EXISTS`),新增字段需同时改 `_SCHEMA`、`_MIGRATIONS`、`models` 读写与 `_row_to_dict`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PK | 短随机 id(8 位十六进制),用作 URL 段 |
| `name` | TEXT | 显示名,默认由目录推导,可改 |
| `kind` | TEXT | `model` / `imagery` / `vector` / `terrain` |
| `root` | TEXT | 服务根目录**绝对路径**,已 `resolve()`,路径穿越检查的基准 |
| `entry` | TEXT | 相对 root 的入口。TMS 为 `""`;模型为 `tileset.json`;矢量为文件名 |
| `grid` | TEXT | 瓦片网格:`geodetic` / `mercator` / `""`(非瓦片) |
| `flip_y` | INTEGER | 行号是否自南向北(TMS 为 1,OSM 为 0) |
| `minzoom` / `maxzoom` | INTEGER | 瓦片级别范围 |
| `bounds_wgs84` | TEXT | JSON 数组 `[w,s,e,n]`,供定位。来源见 3.1.1;取不到为 NULL,前端需有兜底 |
| `bounds_approx` | INTEGER | 范围是否为估算值。两个来源会置 1:`tilemapresource.xml` 的瓦片对齐四至(§3.1.1 优先级 2)、索引扫描超限降级(§3.1.2)。前端据此提示"范围约为估算值" |
| `enabled` | INTEGER | 开关,**默认 0** |
| `source` | TEXT | `output_scan` / `manual` |
| `created_at` | TEXT | ISO 时间 |

#### 3.1.1 范围来源(`bounds_wgs84`)

按优先级取第一个命中的。前两类是**元数据直读**,后三类是**反算**——其中瓦片索引反算是关键,它让**没有任何元数据的 OSM/XYZ 瓦片包也能定位**。

| 优先级 | 类别 | 来源 | 说明 |
|---|---|---|---|
| 1 | 全部 | 同级 `metadata.json` 的 `bbox_wgs84` | 本工具产出的成果都有,最准 |
| 2 | 影像 | `tilemapresource.xml` 的 `BoundingBox` | 属性名是 **`minx` / `miny` / `maxx` / `maxy`**(不是 `west` 等)。**实测该值是"瓦片对齐后的四至"(`tms.py::write_tilemapresource` 用 `mosaic_bounds()` 生成),比真实选区每边最多大出一张瓦片**,故定位够用但不是精确范围。读到它时置 `bounds_approx = 1` |
| 3 | 模型 | `tileset.json` 的 `root.boundingVolume` | **两种形态都要支持**:`region` 为 `[west,south,east,north]` **弧度**,直接转度;`box` 是 `[cx,cy,cz, xAxis..., yAxis..., zAxis...]`(中心 + 三个半轴向量,地心 ECEF 米制),**实测本工具产出的用 `box`**。`box` 取八个角点后取 min/max,再用 `rasterio.warp.transform` 从 EPSG:4978 转 4326。两者都没有时 → 降级为 NULL |
| 4 | 地形 | `layer.json` 的 **`available`** | **不要用 `bounds`**:实测本工具切出的地形 `bounds` 恒为 `[-180,-90,180,90]`(写的是世界范围,不是数据范围)。`available` 是逐级的 `{startX,startY,endX,endY}` 区间,**y 为 TMS 行号(自南向北)**,需按 §3.1.2 同一套换算反算 |
| 5 | 影像 | **扫描瓦片索引区间反算** | 见下,OSM/裸 XYZ 包的兜底 |

#### 3.1.2 瓦片索引反算(优先级 5)

**原理**:扫描瓦片目录得到每个级别的行列区间,用该级别的外接矩形反算经纬度。取**最高级别**的区间——低级别瓦片覆盖范围更粗,高级别最贴合实际数据。

复用项目既有换算函数,不新写坐标逻辑:

| 网格 | 复用函数 | 换算 |
|---|---|---|
| geodetic(天地图 TMS) | `core/tiling.py::tile_bounds(col, row, z)` | 直接得 (w, s, e, n)。**注意行号先翻转**:TMS 自南向北,`core/tms.py::tms_row()` 给出 `xyz_row = 2^(z-1) - 1 - tms_row` |
| mercator(OSM XYZ) | `core/osm.py::tile_bounds_3857(x, y, z)` | 得 3857 米制四至,再 `rasterio.warp.transform_bounds(crs=3857, "EPSG:4326", densify_pts=21)` 转度 |

**目录命名要支持两种**(扫到哪种用哪种):

- `{z}/{x}/{y}.png` —— gdal2tiles / OSM XYZ 标准结构(本工具导出成果)
- `{z}/{col}_{row}.ext` —— 本工具瓦片缓存格式(用户把缓存目录当服务发布时)

**性能保护**:扫描量为文件数。设 **20 万文件上限**;超限则用已扫到的部分并置 `bounds_approx = 1`,前端提示"范围约为估算值"。实测本工具单任务成果在万级,上限内必命中。扫描在**注册时执行一次**,不进入请求路径。

#### 3.1.3 网格类型的判定

反算前要先知道是 geodetic 还是 mercator:

1. 有 `tilemapresource.xml` → 读 **`<TileSets profile="...">` 的 `profile` 属性**(实测本工具写的是 `geodetic`)。它比 `<SRS>` 更直接——`SRS` 只说明坐标系,`profile` 直接是网格名。
2. 无 XML → 看**第 1 级瓦片的行数**:geodetic 的 z=1 只有 1 行(行数 `2^(z-1)`),mercator 有 2 行(行数 `2^z`)。这是两者的结构性差异,不依赖命名约定。
3. 仍判不出 → 默认 **mercator**(XYZ 是更通用的约定),并由用户在注册时手工覆盖。

`flip_y` 与网格绑定:geodetic TMS 目录形态为 1(行号自南向北),mercator 为 0。与 `core/overlay.py::list_layers()` 的判定保持一致。

#### 3.1.4 范围仍为 NULL 时

前端不猜测:定位按钮置灰并提示"该服务没有范围信息,无法定位"。三维类不受此影响——预览页改用 `viewer.zoomTo(tileset)`,不依赖 `bounds_wgs84`;主界面只画范围框,范围框缺失时该服务的定位按钮同样置灰。

**注意**:§3.1.1 的优先级 3/4 都是**尽力而为**的解析。三维数据即使全部解析失败也能用(靠 `zoomTo`),而瓦片类失去范围就只剩手工目视找位置——所以优先级 5 的索引反算是瓦片类的主路径,不是可有可无的兜底。

### 3.2 成果识别规则

新增 `backend/core/service_scan.py`。判据取自**格式规范定义的标志文件**,不是目录命名约定——因此对任意第三方瓦片包同样成立。

| 类别 | 判据 | 实测命中示例 |
|---|---|---|
| 模型 | 递归找到 `tileset.json` | `output/Data/3dtiles/` |
| 地形 | 目录含 `layer.json` | `output/新疆矿_高程/terrain/` |
| 影像 | 含 `tilemapresource.xml`(TMS);或含数字分层子目录且层内有瓦片(OSM/XYZ);或单个 `.tif` | `*/tms/`、`*/osm/` |
| 矢量 | 单个 `.geojson` / `.kml` | `*_contour.geojson` |

**扫描深度限制为 3 层**;只认上述判据文件。识别不出时**回退到手工指定类型**注册(接口接受显式 `kind`),不静默忽略。

扫描不出的常见原因要提示到位:只有裸目录结构、连 `tilemapresource.xml` 都没有的 TMS。

### 3.3 端点

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/services` | 列出已注册服务(含 `enabled`、`overlay_desc`、`access_path`) |
| GET | `/api/services/candidates` | 扫 `settings.output_dir` 得到的候选(未注册的) |
| POST | `/api/services/scan` | 扫任意本地目录 → 候选 |
| POST | `/api/services` | 注册 |
| PATCH | `/api/services/{id}` | 改名 / 开关 |
| DELETE | `/api/services/{id}` | 移除注册记录(**不删文件**) |
| GET | `/api/services/health` | 批量探活,面板打开时调用 |
| GET | `/api/svc/{id}/{path:path}` | **文件服务** |

**`access_path` 返回路径而非完整 URL**:后端只知道 `server.host`(可能是 `127.0.0.1`),而实际访问者可能是 `192.168.x.x` 或域名。前端拼 `location.origin`。

### 3.4 文件服务的安全与错误语义

- `root` 在注册时 `resolve()`。每个请求把 `root/entry/path` 拼接后 `resolve()`,必须 `is_relative_to(root)` → 否则 **403**。`..` 穿越、绝对路径注入、短路径、大小写变体、符号链接逃逸全部过这同一道检查。
- `enabled = 0` → **403 + JSON 说明**("服务未开启")。开关状态与路径写错是两回事,报错必须能区分。
- root 或 entry 不存在 → **410 Gone** + 明确文案("源目录已不存在"),前端据此把卡片标灰。
- **必须处理 Range 请求**(返回 206):`ol/source/GeoTIFF` 直读 tif 依赖它,这是现有 `overlays.js` 里 `cog` 类型的既有前提。
- 3D Tiles 的 `.pnts` / `.b3dm` / `.json` 需正确的 `Content-Type`。
- **不做来源限制**(D4)。代码注释与文档写明:仅当 `server.host` 为 `0.0.0.0` 时才对局域网开放。

### 3.5 服务生命周期与失效处理

服务是持久化的,但磁盘上的目录不是。目录被删/移走后卡片仍在列表,因此必须有移除入口。

| 状态 | 判据 | 卡片表现 | 可用操作 |
|---|---|---|---|
| 已开启 | `enabled=1` 且源存在 | 绿色标记 | 关闭 / 复制地址 / 移除 |
| 已关闭 | `enabled=0` 且源存在 | 灰色标记 | 开启 / 移除 |
| **源失效** | root 或 entry 不存在 | 红字「源目录已不存在」+ 整卡降透明度 | **仅移除**(开启/复制禁用) |

**移除入口三层**:

1. **卡片上的「移除」按钮** — 每个卡片自带,`Popconfirm` 二次确认。**失效状态下依然可点**——目录没了正是最需要移除的时候。
2. **「清理全部失效服务」** — 面板顶部,仅当存在失效服务时出现。文案需提醒:外接盘未挂载时服务会集体假性失效,避免误清。
3. **`DELETE /api/services/{id}`** — 只删注册记录(D6)。

**检测时机**:面板打开时调 `GET /api/services/health` 批量探测一次(纯本地 `Path.exists()`,毫秒级)。不做常驻轮询——目录被删是低频事件。

**与任务删除的关系**:任务被 `purge=True` 删除时 output 目录消失,对应服务随即失效,但**不自动删除服务记录**。自动删会让"目录临时不可用(外接盘没挂上)"变成永久丢失配置。

### 3.6 复用既有能力

- **系统文件对话框**:`POST /api/local/pick`(`kind='dir'` / `'file'`)已实现且有 `DIALOG_TIMEOUT` 与线程池处理,直接复用,不新写。
- **成果扫描**:`core/overlay.py::list_layers()` 的判定逻辑(瓦片扩展名探测、级别范围、`_tiles3d_entry` 多文件点云子目录约定)可提取复用。
- **矢量转换**:`core/local_vector_file` 已有 pyogrio 能力,用于 KML → GeoJSON(见 4.3)。

## 4. 前端设计

### 4.1 服务面板

**入口**:`AppTopBar.vue` 在「任务」之后加「服务」按钮,角标显示**已开启服务数**(对齐现有 `activeCount` 的角标做法)。点击打开 `ServicePanel.vue`(右侧抽屉)。

**布局**:

```
┌─ 服务 ──────────────────────────────── [×] ┐
│ 本地目录: [路径输入________] [浏览…] [扫描]  │  ← 顶部:添加
├────────────────────────────────────────────┤
│ ⚠ 发现 2 个失效服务      [清理全部失效]      │  ← 仅失效时出现
│ 筛选: [全部▾] [关键字______]                │
├────────────────────────────────────────────┤
│ ┌────────────────────────────────────────┐ │
│ │ ● 影像  output/怀化不动产_全量/tms      │ │
│ │   路径: …/output/怀化不动产_全量/tms     │ │
│ │   [复制地址] [关闭] [移除]              │ │
│ └────────────────────────────────────────┘ │
├────────────────────────────────────────────┤
│ ▸ 未注册的成果(6)                          │  ← 可折叠:output 扫描候选
│   ☐ 模型  output/Data/3dtiles              │
│   ☐ 地形  output/新疆矿_高程/terrain        │
└────────────────────────────────────────────┘
```

**交互决策**:

| 项 | 做法 | 理由 |
|---|---|---|
| 候选与已注册分区 | 上半已注册(可操作),下半候选(勾选注册,可折叠) | 候选可能几十个,混排会让已注册服务淹没 |
| 关闭态卡片 | 「复制地址」仍在但置灰 | 让用户知道"有地址、开了就能用",而非以为没配 |
| 复制内容 | `location.origin` + `access_path`,瓦片**保留 `{z}{x}{y}` 占位符原样**,不做 URL 转义 | 转义花括号会让模板失效 |
| 复制反馈 | `MessagePlugin.success('地址已复制')` | 复用项目现有 `tdesign-vue-next` |
| 路径显示 | 中段省略,`title` 给全路径 | 对齐 `LayerPanel.vue` 的 `.lbl` 既有做法 |
| 名称 | 可点击改名,默认「任务名/成果类型」 | 一堆同名 `tms`/`osm`,必须能区分 |

**分类标签配色**沿用项目既有蓝系令牌(`#e0f2fe` 底 / `#0369a1` 字),不引入新配色或新字体——本次是既有产品的增量功能,遵循项目既定设计系统。

**错误提示**(不静默):扫描无成果 → 面板内提示并列出识别规则;注册失败/路径不存在 → 就地红字,不弹窗。

### 4.2 预览页接入

现状 `PreviewApp.vue::init()` 把**任务加载**与**页面初始化**绑死。改造要点:

| 改动 | 说明 |
|---|---|
| `id` 参数变为可选 | 无 `id` 时不再报错,进入空白预览(底图照常加载) |
| 顶栏加「添加服务图层」按钮 | 打开 `ServiceLayerPicker.vue` |
| 服务图层进入现有 `layers` 数组 | 复用已有的 `toggle()` 勾选逻辑与「叠加图层」面板 |
| 初始化后自动定位 | 有 `bounds_wgs84` 时按它飞;为 NULL 时三维用瓦片集 `zoomTo`,二维（瓦片/矢量）不猜测、保持当前视野 |

**`ServiceLayerPicker.vue` 只列 `enabled=1` 的服务**——关掉的服务选中会立刻 403,不如不显示。无开启服务时提示"还没有开启的服务,去「服务」菜单添加"。

**各类别在 Cesium 的渲染**:

| 类别 | 做法 |
|---|---|
| 影像 | `TileMapServiceImageryProvider`(TMS)/ `UrlTemplateImageryProvider`(OSM) |
| 地形 | `CesiumTerrainProvider.fromUrl`,纳入现有 `TERRAIN_KEYS` 互斥体系 |
| 模型 | `Cesium3DTileset.fromUrl` |
| 矢量 | 见 4.3 |

### 4.3 矢量贴地渲染

需求要求"用 primitive、贴地"。Cesium 的实际能力分布:

| 几何 | 贴地方案 | 是否 Primitive |
|---|---|---|
| 面 | `GroundPrimitive` + `GeometryInstance` + `ColorGeometryInstanceAttribute` | 是 |
| 线 | `GroundPolylinePrimitive` + `GroundPolylineGeometry` | 是 |
| 点 | **无贴地 Primitive** | 否,需破例 |

**点要素的处理(用户已确认)**:默认用 **Entity + `heightReference: CLAMP_TO_GROUND`**;当单图层点数**超过 5000** 时自动回退为不贴地的 `PointPrimitive` 并提示用户。代码注释必须写明为什么点要破例,避免后人误以为是随手写法。

**KML 的处理**:`KmlDataSource` 走 Entity 体系,与"用 primitive"冲突。因此 **KML 统一在后端转成 GeoJSON**(复用 `core/local_vector_file` 的 pyogrio 能力),前端只处理 GeoJSON 一种输入。

**已知限制**:`GroundPrimitive` 依赖地形做裁剪,**没有地形时退化为贴在椭球面**。这是 Cesium 固有设计,界面提示需写明。

### 4.4 主界面图层列表接入

现有 `overlayStore` 有三个与任务强绑定的假设,必须解除:

| 约束 | 现状 | 改法 |
|---|---|---|
| `overlayKey(taskId, layerId)` | key 恒为 `${taskId}:${layerId}` | 改为来源无关:服务图层 `svc:${serviceId}`,任务图层 `task:${taskId}:${layerId}` |
| `_fallbackBbox` | 靠 `taskStore.byId(taskId)` 取范围 | 服务图层从服务记录的 `bounds_wgs84` 取 |
| `removeByTask` | 任务删除时清图层 | 补 `removeByService(serviceId)`,服务移除时同步清 |

**`LayerPanel.vue` 改动**:底部「＋ 添加图层」改为下拉,两个来源——「从『数据』面板添加」(现有)与「从『服务』列表添加」(新增,复用 `ServiceLayerPicker.vue`)。

**透明度 / 层级 / 定位自动继承,无需额外开发**:

| 能力 | 为何自动可用 |
|---|---|
| 透明度 | `overlayStore.setOpacity()` → `overlays.js::setOverlayOpacity()`,对任意 `ol/layer` 通用 |
| 上下移层 | `overlayStore.moveUp/moveDown` → `applyOrder()` 按数组顺序重排 `zIndex`,与来源无关 |
| 定位 | `zoomToOverlay()` 读 `desc.bounds_wgs84`,服务图层的 `desc` 带上即可;为 NULL 时 `zoomToOverlay` 返回 false,`LayerPanel` 已有的「该图层没有可用的范围信息,无法定位」提示即生效 |

**这是本设计最重要的约束(D5)**:后端 `GET /api/services` 返回的每个服务都带 `overlay_desc`,结构与 `core/overlay.py::list_layers()` 输出逐字段对齐(`kind` / `label` / `url` / `grid` / `flip_y` / `minzoom` / `maxzoom` / `bounds_wgs84`),这样 `overlays.js::build()` 零改动即可渲染服务图层。

**二维地图的能力缺口**:`overlays.js::build()` 支持 `tiles` / `cog` / `vector` / `vector_convert` / `raster_only_bbox`,**不支持 3D Tiles 与地形**。因此:

- 模型 / 地形类服务在**主界面**表现为**范围框 + 「打开三维预览」按钮**(与现有 `preview3d` 的处理一致)。
- 完整三维查看走预览页。

## 7. 已知限制

| 限制 | 说明 |
|---|---|
| 无 token,不做访问限制 | 服务绑 `0.0.0.0` 时局域网可读已开启的服务。默认 `127.0.0.1` 下仅本机 |
| 点要素破例用 Entity | `GroundPrimitive` 无点类型(见 4.3) |
| 无地形时贴地退化为椭球面 | Cesium 固有行为 |
| 主界面不支持三维渲染 | 模型/地形只画范围框 |
| 不自动感知目录变化 | 打开面板时才探活,不做常驻轮询 |
| 范围反算依赖目录完整性 | 瓦片索引反算扫的是文件;20 万文件上限之外只能给估算范围(`bounds_approx=1`) |
| 网格类型可能判错 | 无 `tilemapresource.xml` 且第 1 级行数无法区分时默认 mercator,需手工覆盖 |
| 完全识别不出的数据需手工指定类型 | 既无判据文件、又无数字分层瓦片目录的,扫描会漏,回退到手工注册 |
| 外接盘未挂载会假性失效 | 服务列表会集体显示"源不存在",移除前需确认盘已挂载 |
