# 图层底图 ↔ 下载数据源 双向同步 — 设计文档

> 日期:2026-09-29
> 范围:图层面板的「底图」选择与下载对话框的「数据源」选择双向同步
> 需求来源:`docs/input/新增需求/需求描述2.md` 的需求34(截图 `image-8.png` / `image-9.png`)

## 1. 问题与目标

### 现状

两个控件分别控制同一件事的两个侧面(底图是"看什么",数据源是"下什么"),但**互不相通**:

| 方向 | 现状 |
|---|---|
| 数据源 → 底图 | 有,但**只覆盖天地图三项** —— `ProcessDialog.vue:550` 写死 `['tianditu_img','tianditu_vec','tianditu_ter']`,切到 Google/Esri 时底图不动 |
| 底图 → 数据源 | **完全没有**。`LayerPanel.vue:98` 只调 `basemapStore.setKey(v)`,从不通知对话框 |

更关键的是 `resetFormState()`(`ProcessDialog.vue:476`)把 `form.provider` **写死回 `'tianditu_img'`**,而它**每次打开对话框都会执行**(`initForCurrentSource` 的第一行)。所以:

> 底图已经是 Google 卫星影像 → 打开下载对话框 → 数据源仍默认「天地图影像」。

### 目标

1. **底图 → 数据源**:图层面板切换底图后,**立即**改写对话框的数据源 —— 但仅当该底图**在下载数据源列表中**。
2. **数据源 → 底图**:切换数据源后,**立即**切换底图 —— 但仅当该数据源**在底图列表中**。
3. **默认值跟随**:打开对话框时,数据源的初始值取自当前底图(同样受"在下载列表中"约束)。

### 非目标(本次不做)

- **`RedownloadDialog` 的同步**。它有自己的数据源列表,需求未提及。
- **两个列表的合并/统一**。它们本就不同(见 §3),本次只在交集上同步。
- **记忆用户上次的选择**。默认值跟底图,不做持久化偏好。

### 已确认的取舍

| # | 取舍 | 决定 | 影响 |
|---|---|---|---|
| Q1 | 同步强度 | **立即改写当前表单**(非仅改默认值) | 两个控件永远一致;代价见 §6 风险 |
| Q2 | 成员判定 | **切换目标必须在对方列表中**,不在则不做处理 | 避免把 `esri_terrain` 设成底图这类无效组合 |
| Q3 | 打开时的初始值 | **跟随底图**(底图不在下载列表则回落天地图影像) | 否则关闭重开会丢失同步,「默认选择图层」的诉求落空 |

## 2. 两个列表的实际内容(实测)

| 列表 | 位置 | 内容(8 项) |
|---|---|---|
| 底图 | `utils/basemap.js::BASEMAP_OPTIONS` | 天地图影像 / 矢量底图 / 地形晕渲、Google 卫星影像、**Google 含路网**、**Google 路线图**、**Google 地形**、Esri World Imagery |
| 下载数据源 | `ProcessDialog.vue::providerOptions` | 天地图影像 / 矢量底图 / 地形晕渲、Google 卫星影像、Esri World Imagery、**Esri DEM**、**三维建筑白模(OSM)**、**三维建筑白模(本地矢量面)** |

**只有 5 个键重合**,这正是同步必须带成员判定的原因:

| | 键 |
|---|---|
| **交集(可同步)** | `tianditu_img`、`tianditu_vec`、`tianditu_ter`、`google_img`、`esri_imagery` |
| **只在底图** | `google_hybrid`、`google_road`、`google_terrain` |
| **只在下载列表** | `esri_terrain`、`osm_buildings`、`local_vector` |

> 交集的键名完全相同,所以"映射"退化为**成员判定**:底图的键在不在下载列表里、数据源的键在不在底图列表里。

## 3. 核心设计决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | **同步逻辑留在 `ProcessDialog` 内部,不提升表单状态** | `form.provider` 是对话框的局部表单状态,离开对话框即无意义。提升到 store 会让 store 承担表单职责,且 `resetFormState` 还要反过来读写它。 |
| D2 | **成员判定各自留在列表所在处** | 下载列表在 `ProcessDialog`(用它自己的 `providerOptions` 派生);底图列表在 `basemap.js`(导出一个 `isBasemapKey`)。不在别处硬编码交集数组 —— 那种写法在列表增删时必然漂移。 |
| D3 | **两个方向都加"值未变则跳过"的守卫** | 两个 watch 互相触发会成环。设同值不触发 Vue watcher,所以本就收敛;但 `basemapStore.setKey` 会 `apply()`(移除并重建底图图层),不守卫会导致**每次打开对话框都闪一下**。 |
| D4 | **`resetFormState` 的 provider 初始值改为"跟随底图"** | 否则关闭重开会把它重置回天地图影像,Q3 的诉求落空。 |
| D5 | **不改 `RedownloadDialog`** | 需求未提及,且它按源任务类型过滤数据源,语义不同。YAGNI。 |

## 4. 实现设计

### 4.1 `utils/basemap.js`:导出成员判定

```js
/** 该 key 是否是底图列表中的一项。用于「数据源 → 底图」的成员判定。 */
export function isBasemapKey(key) {
  return BASEMAP_OPTIONS.some((x) => x.value === key)
}
```

### 4.2 `ProcessDialog.vue`:双向同步

**⓪ 补 import**

该组件目前**未**从 `utils/basemap` 导入任何东西,需要新增:

```js
import { isBasemapKey } from '../utils/basemap'
```

**① 派生本对话框的可下载键集合**(放在 `providerOptions` 定义之后)

```js
// 本对话框可下载的数据源。用于「底图 → 数据源」的成员判定 ——
// 从 providerOptions 派生而不是另抄一份,列表增删时不会漂移。
const DOWNLOAD_KEYS = new Set(providerOptions.map((o) => o.value))
```

**② 方向一:数据源 → 底图**(扩展现有 watch)

```js
watch(() => form.provider, async () => {
  if (!isDownload.value) return
  applyDownloadDefaults()
  // 仅当该数据源在底图列表中存在时才切底图。
  // 原实现写死三个天地图键,切到 Google/Esri 时底图不动。
  if (isBasemapKey(form.provider) && basemapStore.key !== form.provider) {
    basemapStore.setKey(form.provider)
  }
  await loadSuggest()
  await loadEstimate()
  await loadDemMaxLevel()
  await loadImgMaxLevel()
})
```

**③ 方向二:底图 → 数据源**(新增 watch)

```js
// 底图切换 → 同步数据源。仅当该底图在本对话框可下载时才改;
// 如 Google 路线图只在底图列表里,切到它不动数据源。
watch(() => basemapStore.key, (k) => {
  if (!isDownload.value) return
  if (!DOWNLOAD_KEYS.has(k)) return      // 不在下载列表 → 不动
  if (form.provider === k) return        // 已是它 → 不动(见 D3)
  form.provider = k                      // 触发上面的 watch 回写底图,幂等收敛
})
```

**④ 打开时的初始值**

```js
function resetFormState() {
  form.name = ''
  // 数据源默认跟随当前底图(仅当该底图可下载),否则回落天地图影像。
  // 原实现写死 'tianditu_img',导致切了底图再打开对话框又被重置。
  form.provider = DOWNLOAD_KEYS.has(basemapStore.key)
    ? basemapStore.key
    : 'tianditu_img'
  ...
}
```

> **只需 `DOWNLOAD_KEYS.has` 一个条件**,不需要再判 `isBasemapKey`:
> `basemapStore.key` 只可能取自 `BASEMAP_OPTIONS`(见 `LayerPanel` 的 `@change`
> 与 store 的 `setKey` 默认值),所以它必然是底图键。于是
> `DOWNLOAD_KEYS.has(basemapKey)` 恰好等价于"两个列表的交集",
> 而 `google_road` 这类只在底图的键自然为假。多加一个 `isBasemapKey`
> 是冗余的,还会让人误以为存在非底图来源的 key。

### 4.3 界面提示

数据源下拉旁加一句说明它跟随底图,避免"我只想切底图看图,下载源怎么被改了"的困惑:

```html
<span class="dim">（跟随图层底图,切换底图时同步）</span>
```

## 5. 边界与错误处理

| 场景 | 行为 |
|---|---|
| 底图切到 `google_road`(只在底图) | 数据源**不动**(不在下载列表) |
| 数据源切到 `esri_terrain`(只在下载列表) | 底图**不动**(不在底图列表) |
| 数据源切到 `osm_buildings` / `local_vector` | 同上,底图不动 |
| 对话框未打开时切底图 | watch 仍会执行(`basemapStore.key` 变化即可),数据源被改写;下次打开时 `resetFormState` 按底图取值 —— 结果一致 |
| 对话框处于非"下载"来源(三维/本地文件) | `!isDownload.value` 直接返回,不做任何同步 |
| 两边已是同一个键 | 跳过,不调 `setKey`(避免重建图层造成闪烁) |
| 底图是 `google_road`,打开对话框 | 数据源回落 `tianditu_img`(底图不可下载) |

## 6. 已知风险(用户已确认接受)

**强耦合**:切换底图会**连带改变下载目标**。

典型误伤场景:用户只想把底图临时切到「Google 地形」看地貌 —— 这个键不在下载列表,数据源不受影响(好);但若切到「天地图矢量底图」,下载源就会被改成天地图矢量底图。

缓解措施:
- §4.3 的界面提示,让用户知道数据源跟随底图
- 只有 5 个交集键会触发同步,3 个纯底图键(Google 含路网/路线图/地形)天然安全

> 这是用户明确选择的取舍(不是仅改默认值)。若日后觉得误伤频繁,可退回到"仅改默认值"——改动很小(去掉方向二的 watch,`resetFormState` 保留)。

### 7.3 手工验证清单

1. 底图切「Google 卫星影像」→ 打开下载对话框,数据源应为 **Google 卫星影像**。
2. 对话框开着时,底图切「Esri World Imagery」→ 数据源应**立即**变成 Esri World Imagery。
3. 对话框开着时,数据源切「全国地形 DEM」→ 底图应**不动**。
4. 底图切「Google 路线图」→ 数据源应**不动**。
5. 数据源切「三维建筑白模(OSM)」→ 底图应**不动**。
6. 底图切「天地图矢量底图」→ 数据源变天地图矢量底图,且**级别/格式按新类型重置**(既有行为不回归)。
7. 来回切换底图与数据源数十次,确认**不闪屏、不卡顿**(D3 守卫生效)。
8. 底图是 Google 路线图时打开对话框 → 数据源应为**天地图影像**(回落)。
