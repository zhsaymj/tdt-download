# 3D Tiles 分层优化设计

## 背景与诊断

数据 A 的根 `tileset.json` 为 101,417,644 字节、内嵌 38,498 个节点，最大深度 16；数据 B 的根清单为 109,012 字节、402 个节点，最大深度 4。A 的主清单把 384 个 Tile 的完整子树全部内联，导致 Cesium 首次解析和调度成本过高。A 的根误差为 46,088，而水平包围盒只有约 546 × 444 米；B 同尺度根误差约 351。A 的误差过大，会使远景持续细化。

进一步检查发现，A 的 `_pyramid` 只占少量顶层节点，提供远景粗模型；直接关闭会损失远景 LOD。因此保留金字塔，只外置每个 Tile 的完整子树。A 还包含 5 个指向不存在 b3dm 的内容引用。

## 目标

1. 保留现有 b3dm、坐标变换、纹理和完整细节 LOD。
2. 根清单控制在与 B 接近的 KB 级，Tile 子树通过外部 tileset 按需加载。
3. 将根和金字塔的误差调整到与场景尺度相符，并保持 Tile 内部原有相对 LOD 比例。
4. 剔除不存在的内容引用；有有效后代时保留其节点结构。
5. 转换后自动优化；优化失败时原始清单仍可预览。
6. 服务扫描只注册整套模型，不把外部 Tile 清单注册成独立服务。

## 实现

### 清单优化器

`backend/core/tileset_optimizer.py` 读取转换器输出的 `tileset.json`，识别 `Data/Tile_*` 子树。每个子树写到原 Tile 目录内的 `tileset.json`，内部 b3dm URI 改为相对该目录。主清单保留包围盒、误差和外部 JSON URI；`_pyramid` 节点及其 b3dm 原样保留。

输出结构：

```text
3dtiles/
  tileset.json
  Data/
    _pyramid/*.b3dm
    Tile_*/
      tileset.json
      *.b3dm
```

根误差取水平包围盒半对角线；首个金字塔内容节点的误差取最大水平跨度除以 144，逐层减半，最低到首层的八分之一。Tile 外链误差与所在金字塔层衔接，Tile 内节点按原始误差比例缩放。该规则由 A/B 同尺度样例校准，需在其他尺度数据上继续验证视觉效果。

先检查内容文件是否存在，缺失内容被剔除，仍有子节点的节点保留。所有外部清单验证通过后写盘，最后原子替换主清单。重复运行不会继续拆分。失败时根清单保持原样，但可能留下未引用的外部清单。

### 任务与服务

`runner_3d.py` 在 OSGB 转换成功后调用优化器，记录外部 Tile 数、清单大小变化与缺失引用数。优化异常只产生中文警告，不把有效的原始转换成果判为失败。

`service_scan.py` 在扫描整套模型时忽略根 `Data/Tile_*/tileset.json`；直接选择单个 Tile 目录时仍可识别它。

## 验证

- 单元测试覆盖外部 URI、误差归一化、失效内容剔除、重复执行、任务管线接线和服务扫描去重。
- A 样例生成优化清单，不重新转换 b3dm；完整遍历根与外部清单，检查 URI 存在性和父子误差单调性。
- 对 B 记录结构基线。浏览器 FPS、请求数和显存仍需在目标机器上做 Cesium 实测，静态结构指标不等同于帧率结论。

## 边界

本次只处理 OSGB 转换输出，不改变 LAS/LAZ 和建筑物的 3D Tiles 管线。已有 A 成果保留原清单备份并启用优化入口。未提供单独的界面开关，旧成果可用备份清单回退。
