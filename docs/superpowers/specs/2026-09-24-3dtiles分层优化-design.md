# 3D Tiles 分层优化设计

## 背景

当前 OSGB 转换结果 A 的 `tileset.json` 约 101 MB，包含约 38,498 个内嵌节点，Cesium 远景加载时出现明显卡顿。参考结果 B 的 `tileset.json` 约 109 KB，仅约 402 个节点，采用较浅的空间层级和外部内容引用，整体浏览流畅。

## 目标

1. 保留 L18-L23 等有效细节层级和原有坐标、纹理结果。
2. 将发布树改造成稀疏空间层级，控制在 4-6 个逻辑层级。
3. 根 `tileset.json` 只保留少量一级空间块，不再内嵌全部节点。
4. 远景优先加载粗模型，放大后按 `geometricError` 加载高精度模型。
5. 清理 `_pyramid` 产生的冗余节点、空节点和重复包围盒。
6. 保持旧成果可继续预览，并允许通过开关回退旧输出方式。

## 方案

### 转换器

- 保留原始 OSGB 到 b3dm 的转换流程。
- 顶层金字塔默认关闭，新增配置或命令行选项控制是否启用。
- 转换完成后生成稀疏发布树：根节点按空间块分组，子层级按原始 LOD 归并。
- 当子树规模超过阈值时写成独立的外部 `tileset.json`，主清单仅保留 URI、包围盒、误差和子节点。
- 删除没有内容和没有有效子节点的节点。
- 父节点 `geometricError` 使用子节点最大误差乘以安全系数，确保误差从根到叶单调递减。

### 输出结构

```text
3dtiles/
  tileset.json
  tileset_nodes/
    <空间块>.json
  Data/
    <原始或优化后的 b3dm 文件>
```

保留现有 `tileset.json` 入口；前端无需改 URL。

### 兼容和回退

- 旧模式继续支持 `--no-pyramid` 或兼容参数。
- 优化模式失败时保留原始转换产物，并返回清晰的中文警告。
- 已生成的旧成果不强制重写，可通过独立优化命令处理。

## 验证

### 自动化验证

- 解析输出树，检查无空节点、无失效 URI、无循环引用。
- 检查最大逻辑层级在 4-6 层范围内。
- 检查每个父节点误差不小于子节点误差。
- 检查根清单大小、节点数和外部引用数量。
- 使用现有 3D Tiles 相关测试回归。

### 样例验证

使用数据 A 和数据 B 对比：

- 根清单大小和节点数量；
- 首次加载时间、远景 FPS、局部放大 FPS；
- 请求数量和浏览器内存；
- 坐标落点、纹理、模型完整性。

## 风险

- 外部 tileset 增多会增加 HTTP 请求，需要设置合理拆分阈值。
- 过度压缩层级可能导致局部加载不连续，因此保留原始高 LOD 叶节点。
- 不同 OSGB 数据的空间分布差异较大，阈值需要通过 A/B 样例校准。
