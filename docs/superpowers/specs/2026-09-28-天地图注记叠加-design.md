# 天地图路网注记叠加 — 设计文档

> 日期:2026-09-28
> 范围:① Google/Esri 下载支持烘焙天地图注记 ② 图层面板新增独立的注记显示开关 ③ 预览底图不再自带注记
> 前置:本设计基于 2026-09-28 的实测结论(见 §2),未实测的部分已明确标注。

## 1. 问题与目标

### 现状

- **注记只有天地图源能用**。`providers/tianditu.py::ANNOTATION_OF` 只映射天地图 key;上一轮我给 runner 加了 `grid_of(provider) != GEO_MERCATOR` 守卫,墨卡托源(Google/Esri)的注记被直接跳过。
- **预览底图把注记和影像绑在一起**。`utils/basemap.js` 里天地图影像是 `types: ['img_w', 'cia_w']`——影像与注记作为一个图层组一起显示/隐藏,用户无法单独控制。
- **注记能力本身是现成的**。`core/annotate.py` 已有「读注记(含带透明色表的调色板 PNG)」+「alpha over 合成」,且已被 mosaic / tms / osm 三条导出链路复用。

### 目标

1. 下载 **Google / Esri** 影像时,可勾选「叠加路网注记」,把天地图注记烘焙进成果(GeoTIFF / TMS / OSM)。
2. 图层面板新增**独立的注记勾选框**,控制预览底图上的注记显示;该层永远位于底图的最上层。
3. 预览底图(天地图三项)**不再自带注记**——注记改由上述勾选框单独控制。

### 非目标(本次不做)

- **下载时移除注记**。明确不改:天地图源下载仍可烘焙注记。
- **注记类型的手动选择**。跟随底图类型自动配对,不给下拉。
- **注记的样式/过滤**(如只显示道路不显示地名)。天地图注记是一整层,不可拆分。
- **给 z19+ 生成注记**。天地图注记最高 z18,不补级(见 §2.2)。

## 2. 实测结论(本设计的事实基础)

以下均为 2026-09-28 在本机实测(经 `backend.config` 的真实密钥)。

### 2.1 天地图注记提供 3857 网格版本 —— 这是整个方案的立论基础

请求同一地点(北京 116.386, 40.0)在**各自正确行列号**下的瓦片:

| 图层 | 网格 | 行列号 | status | size | 编码 |
|---|---|---|---|---|---|
| `cia_w` | 3857 | (53955, 24810) | 200 | 4822B | 1 波段 **palette** PNG,有 colormap |
| `cia_c` | 4326 | (53955, 9102) | 200 | 5202B | 1 波段 **palette** PNG,有 colormap |

**两者编码一致、体量接近**,说明 `_w` 与 `_c` 是同一份注记在两套网格下的投影。

这带来一个决定性的简化:**Google/Esri 本身就是 3857**,与 `cia_w` **同格**——可按行列号直接对取,**零重采样**。

> 前端底图本来就用 `TILEMATRIXSET=w`(`useMap.js:81`),而后端下载用 `c`(`tianditu.py:72`)。这是两套网格并存、各取所需的既有事实。

### 2.2 注记的级别上限是 z18

北京同一点位逐级取 `cia_w`,统计不透明像素:

| 级别 | status | size | 不透明像素 |
|---|---|---|---|
| z16 | 200 | 4822B | 6301 / 65536 |
| z17 | 200 | 2643B | 1802 / 65536 |
| z18 | 200 | 1916B | 2191 / 65536 |
| **z19** | 200 | **213B** | **0 / 65536** |
| **z20** | 200 | **213B** | **0 / 65536** |
| **z21** | 200 | **213B** | **0 / 65536** |

z19 起返回 **HTTP 200 + 213 字节空图**(0 不透明像素),不是 404。

**而 Google 开放到 z21。** 故 z19~z21 的成果**没有注记可叠**,这是硬约束。

> ⚠️ 该空图是 HTTP 200 且体量小,若不识别会被缓存与拼接入成果。本设计对注记下载**直接裁剪到 z18**(§4.2),不让空图进入流程。

### 2.3 同格对齐验证

用「该有路网的地方应不透明」作为对齐判据(z16,`cia_w`):

| 位置 | 不透明像素 | 判读 |
|---|---|---|
| 北京城区 | 6301(9.6%) | 有路网 ✓ |
| 拉萨城区 | 9854(15.0%) | 有路网 ✓ |
| 塔克拉玛干沙漠 | **0** | 无路网 ✓ |
| 太平洋 | **0** | 无路网 ✓ |

沙漠与海洋为 0、城区非 0 —— **地理定位正确**。若网格错位,海洋中会出现注记。

### 2.4 注记编码与现有读取能力的匹配

`core/annotate.py::read_annotation_rgba` 已支持本设计需要的两种编码:

- RGBA PNG → 直接取 4 波段
- **带透明色表的调色板 PNG → 把 `(R,G,B,A)` 色表展开为 rgb + alpha**

天地图注记正是后者(§2.1 实测 `1 波段 palette`)。**故读取与合成代码无需改动**,只需保证注记瓦片按 3857 下载到预期路径。

> 对比:`core/mosaic.py::_read_tile` 的调色板展开只取 `v[:3]`,**丢弃 alpha**——它服务的是底图(不透明),不能用于注记。注记必须走 `annotate.py` 这一路。

### 2.5 合成能力的复用现状

`composite_annotation(base_rgb, anno_path)` 已被三条链路调用:

| 链路 | 位置 | 说明 |
|---|---|---|
| GeoTIFF 拼接 | `mosaic.py:131` | 逐瓦片读底图 → 合成注记 → 落画布 |
| TMS 导出 | `tms.py:166` | 注记开启时逐瓦片解码合成 |
| OSM 导出 | 无 | 源用已烘焙注记的 GeoTIFF,**天然继承** |

**结论:合成层零改动。** 本设计只解决「注记从哪来」和「界面怎么控」。

## 3. 核心设计决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | **注记按源网格选矩阵集(`_w` / `_c`),不做重采样** | §2.1 实测 `cia_w` 与 Google/Esri 同为 3857、编码一致。同格直接对取,零重采样——重采样既慢又有损,且完全没必要。 |
| D2 | **注记复用底图的瓦片区间 `tr`,不另算** | runner 里底图与注记已经在用同一个 `tr`(`runner.py:270-273`),而 `tr` 由 `_range_fn_for(provider)` 按网格产生。注记走同一路径即天然对齐,不需要第二套坐标换算。 |
| D3 | **注记下载裁剪到 z18(常量 `ANNOTATION_MAX_Z`)** | §2.2 实测 z19+ 返回 213B 空图。裁剪避免:① 白跑请求 ② 空图进缓存 ③ 空图被当有效数据。 |
| D4 | **合成层完全复用 `core/annotate.py`,不新增** | §2.4/§2.5:读取已支持带透明色表的调色板 PNG,合成已被三条链路复用。新增只会造成两套实现漂移。 |
| D5 | **预览底图不再绑注记,注记独立成开关** | 用户明确要求。也让"看起来有路网"与"成果里有路网"两件事解耦。 |
| D6 | **注记类型跟随底图自动配对** | 复用后端的 `ANNOTATION_OF` 语义(影像→cia、矢量→cva、地形→cta)。Google/Esri 是影像,配 `cia`。给用户下拉是多余的选择负担。 |
| D7 | **注记勾选框默认开启** | 天地图底图原本"影像+注记"一起显示,拆开后不默认开会让用户觉得"路网没了"——保持观感不变。 |
| D8 | **注记层 zIndex = 底图当前 zIndex + 1** | 用户选择"跟随底基层级"。语义上注记属于底图组:底图被调到成果图层之上时,注记跟着上去。 |
| D9 | **z18 上限做「提示 + 部分生效」,不静默** | 上一轮刚修掉一类"勾了没效果"的坑(Google/Esri 的注记勾选)。这次不重犯:部分有效照常生效,全部超限则置灰说明。 |

## 4. 后端设计

### 4.1 注记 provider 支持矩阵集

`providers/tianditu.py`:

```python
class TiandituProvider(TileProvider):
    def __init__(self, key: str, token: TokenSource, matrix_set: str = "c"):
        ...
        self.matrix_set = matrix_set      # "c"=4326(默认,保持现状) / "w"=3857

    def tile_url(self, col, row, z) -> str:
        sub = next(self._sub)
        # LAYERS 里存的是 "c" 形式(如 "cia_c")。matrix_set 只换末位后缀:
        # "cia_c"→"cia_w"。断言后缀避免哪天 LAYERS 格式变了却静默拼出错 URL。
        assert self.layer_type.endswith("_c"), self.layer_type
        layer_type = self.layer_type[:-1] + self.matrix_set
        return (... f"&TILEMATRIXSET={self.matrix_set}&FORMAT=tiles"
                f"&TILEMATRIX={z}&TILEROW={row}&TILECOL={col}&tk={...}")
```

**默认 `"c"` 保证现有天地图下载行为逐字节不变。**

`ANNOTATION_OF` 增加墨卡托源(Google/Esri 都是影像 → 配影像注记):

```python
ANNOTATION_OF = {
    "tianditu_img": "tianditu_cia",
    "tianditu_vec": "tianditu_cva",
    "tianditu_ter": "tianditu_cta",
    # Google/Esri 是影像源,配影像注记(cia_w)
    "google_img": "tianditu_cia",
    "google_hybrid": "tianditu_cia",
    "google_road": "tianditu_cia",
    "google_terrain": "tianditu_cia",
    "esri_imagery": "tianditu_cia",
}
```

`build_annotation_provider(base_key, token_src, grid="geodetic")`:
- `grid == GEO_MERCATOR` → `matrix_set="w"`,否则 `"c"`
- 注记 key 不存在时返回 `None`(保持现有语义)

### 4.2 runner 接入

`core/runner.py` 三处:

**① 去掉上一轮加的守卫**

```python
# 原(上一轮为禁掉 Google/Esri 而加):
annotate = (task.get("annotate", False) and not is_dem
            and local_src is None
            and grid_of(task["provider"]) != GEO_MERCATOR)
# 改为(本地源与 DEM 仍无注记;墨卡托源现在支持):
annotate = (task.get("annotate", False) and not is_dem
            and local_src is None)
```

**② 注记 provider 按源网格构造**

```python
anno_provider = (build_annotation_provider(task["provider"], anno_token_src,
                                           grid=grid_of(task["provider"]))
                 if annotate else None)
```

**③ 注记下载单独裁剪到 z18**

底图仍下全部选中级别,注记只下 `≤ ANNOTATION_MAX_Z` 的部分:

```python
ANNOTATION_MAX_Z = 18     # 实测天地图注记最高 z18,z19+ 返回 213B 空图(§2.2)

anno_levels = [z for z in levels if z <= ANNOTATION_MAX_Z]
for z in levels:
    tr = range_fn(west, south, east, north, z)
    _ok, _fail, stopped = await downloader.download_range(tr, on_progress, should_stop)
    if stopped: break
    if anno_downloader is not None and z in anno_levels:
        _ok, _fail, stopped = await anno_downloader.download_range(tr, on_progress, should_stop)
        if stopped: break
```

> 注意 `tr` 由底图循环产生,**注记直接复用同一个 `tr`**(D2)。这是"天然对齐"的实现点。

### 4.3 估算按「实际会下注记的级别」加增量,不整体翻倍

`api/tasks.py::api_create_task` 里,`detail = _estimate_detail(...)` 已经算出了**逐级别**的 `levels: [{z, tiles, bytes, ...}]`。直接用它,不必再算一次:

```python
ANNOTATION_MAX_Z = 18      # 与 runner 同名常量,注释互相指向

# 注记只对 ≤ z18 的级别下载(§2.2),故增量 = 那些级别的瓦片数,而非 total*2。
# 逐级别明细已在 detail 里,直接筛出来求和。
if data.annotate and has_annotation:
    anno_tiles = sum(r["tiles"] for r in detail["levels"]
                     if r["z"] <= ANNOTATION_MAX_Z)
    total += anno_tiles
    est_bytes += anno_tiles * _avg_bytes_for(data.provider)
```

现有代码是 `total *= 2; est_bytes *= 2`(整体翻倍),在天地图场景下等价(级别全 ≤18),但**对 Google 会高估**:

| 场景 | 实际会下的注记 | 整体翻倍的结果 |
|---|---|---|
| 天地图 z15~18 | 全部 4 级 | 与逐级求和一致 ✓ |
| Google z16~18 | 全部 3 级 | 一致 ✓ |
| Google z19~21 | **0 张** | **虚高一倍** ✗ |

> 这是上一轮「估算与实际不符」问题的同族变体:不是算错数学,而是没把"注记有级别上限"这个约束带进估算。

## 5. 前端设计

### 5.1 预览底图去掉自带注记

`utils/basemap.js` 的三项 `types` 去掉注记层:

| 底图 | 原 types | 新 types |
|---|---|---|
| `tianditu_img` | `['img_w', 'cia_w']` | `['img_w']` |
| `tianditu_vec` | `['vec_w', 'cva_w']` | `['vec_w']` |
| `tianditu_ter` | `['ter_w', 'cta_w']` | `['ter_w']` |

新增注记映射(与后端 `ANNOTATION_OF` 同语义,前端只关心矩阵集后缀):

```js
/** 底图 → 配对的天地图注记图层(3857)。无配对返回 null。 */
const ANNOTATION_OF_BASEMAP = {
  tianditu_img: 'cia_w',
  tianditu_vec: 'cva_w',
  tianditu_ter: 'cta_w',
  // Google/Esri 是影像源 → 影像注记
  google_img: 'cia_w',
  google_hybrid: 'cia_w',
  google_road: 'cia_w',
  google_terrain: 'cia_w',
  esri_imagery: 'cia_w',
}

export function annotationLayerOf(basemapKey) {
  return ANNOTATION_OF_BASEMAP[basemapKey] || null
}
```

### 5.2 注记图层管理

`composables/useMap.js` 新增:

```js
let annoLayer = null
let annoVisible = true                       // D7:默认开启

function annoLayerZ() {
  // D8:跟随底图层级 —— 底图 zIndex + 1,始终"在底图的最上层"
  return basemapZIndexForLevel(baseLevel) + 1
}

function applyAnnotation() {
  const layerType = annotationLayerOf(baseKey)
  // 移除旧的(底图切换时注记类型要跟着换)
  if (annoLayer) { map.removeLayer(annoLayer); annoLayer = null }
  if (!annoVisible || !layerType || !baseToken) return
  annoLayer = new TileLayer({
    source: new XYZ({
      url: `https://t{0-7}.tianditu.gov.cn/${layerType}/wmts?`
         + `SERVICE=WMTS&REQUEST=GetTile&VERSION=1.0.0`
         + `&LAYER=${layerType.split('_')[0]}`
         + `&STYLE=default&TILEMATRIXSET=w&FORMAT=tiles`
         + `&TILEMATRIX={z}&TILEROW={y}&TILECOL={x}&tk=${baseToken}`,
      crossOrigin: 'anonymous',
      maxZoom: 18,                            // §2.2 注记只到 z18
    }),
    zIndex: annoLayerZ(),
  })
  map.addLayer(annoLayer)
}

function setAnnotationVisible(on) { annoVisible = !!on; applyAnnotation() }
```

`setBasemap()` 末尾与 `setBasemapLevel()` 里都要调 `applyAnnotation()`——前者因底图切换要换注记类型,后者因层级变化要更新 zIndex。

> **注记层不带 `removable`**:它不是用户添加的成果图层,而是底图的附属层,与底图同生命周期。

## 6. 错误处理与边界

| 场景 | 处理 |
|---|---|
| 注记瓦片缺失/解码失败 | `composite_annotation` 已 fail-safe:原样返回底图,**不阻断**成果产出 |
| 注记下载失败(网络) | 与底图同款重试;失败计入 failed。**不因注记失败而判任务失败**(注记是增值项) |
| z19+ 选了注记 | 注记下载直接跳过这些级别(§4.2),成果正常产出、对应级别无注记。界面已在选项处提示 |
| 天地图 token 未配置 | 底图与注记都不加载,保持现有降级行为 |
| 底图切到无配对的源 | `annotationLayerOf` 返回 `null` → 不加载注记层(勾选框置灰) |
| 预览时注记 404(z19+) | OL XYZ 源设 `maxZoom: 18`,超出不再请求 |

### 7.3 手工验证清单

1. **后端对齐(核心)**:下载 Google z16~18 带注记,**在 QGIS 打开**,确认路网与影像对齐、无偏移。
